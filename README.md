# MiniDesk — простой удалённый экран на Python

`client.py` работает у человека, который предоставляет доступ. `control.py` работает
у оператора. Оба приложения имеют интерфейс Tkinter. Отдельный
`signaling_server.py` помогает им найти друг друга через TCP-сокет с TLS.
Сам экран, голос и команды передаются **напрямую по WebRTC (aiortc)**, а не через
signaling-сервер. Низкоуровневые ICE, DTLS, SRTP и видеокодек реализованы библиотекой.

Это прототип для Windows с одним монитором: без клавиатуры, передачи файлов,
автозапуска и фонового доступа. Проверен на Python 3.12 под Windows.
Signaling-сервер также можно запустить на Linux. Клиенты на macOS/Linux требуют
соответствующих разрешений ОС и отдельно не проверялись; Wayland не поддерживается.

## Что умеет

- Одноразовый код подключения; после завершения сессии нужен новый код.
- До явного согласия клиента нет захвата экрана и P2P-медиасессии.
- Просмотр одного экрана с сохранением пропорций, по умолчанию 1280 px и 15 FPS.
- Кнопка запроса мыши у оператора и отдельное подтверждение у клиента.
- Перемещение, левая/средняя/правая кнопки, двойной щелчок, перетаскивание и колесо.
- Кнопка отзыва мыши и отключения у клиента. При потере соединения нажатые удалённо
  кнопки отпускаются.
- Микрофон **оператора → динамики клиента**. По умолчанию выключен. Пока выключен,
  устройство микрофона не открывается. Микрофон клиента не используется.
- Запросы согласия автоматически отклоняются через 60 секунд.

## 1. Установить зависимости на обоих компьютерах

Установите Python 3.12 с Tkinter (обычный установщик python.org включает его).
Скопируйте файлы проекта на оба ПК, откройте терминал в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для команд ниже используйте Python этого окружения. Можно активировать окружение
или вместо `python` писать `.\.venv\Scripts\python.exe`.

## 2. Подготовить signaling-сервер

На машине с доступным IP достаточно файлов `signaling_server.py`, `protocol.py`,
`config.py` и `requirements-server.txt`:

```text
python -m pip install -r requirements-server.txt
python signaling_server.py --init-cert
python signaling_server.py
```

Для Linux команды обычно начинаются с `python3`; зависимости ставьте в venv.
Откройте входящий **TCP 8765** на firewall сервера, при необходимости настройте
проброс порта на маршрутизаторе. Сервер слушает `0.0.0.0`.

`--init-cert` создаст два файла:

- **`signaling_cert.pem`** — скопируйте его по доверенному каналу в папку проекта
  на **оба** компьютера. Это сертификат, которому клиенты доверяют.
- **`signaling_key.pem`** — оставьте только на сервере. Не публикуйте и не
  пересылайте его пользователям.

Сертификат действителен год. Если меняете сертификат, обновите его копию на обоих ПК.
Сервер откажется автоматически перезаписывать существующий сертификат/ключ.
На Linux ограничьте доступ к ключу: `chmod 600 signaling_key.pem`.

## 3. Указать IP и порт

На обоих ПК откройте начало **`config.py`**:

```python
SIGNALING_IP = "127.0.0.1"  # Замените на IP вашего сервера
SIGNALING_PORT = 8765
```

Порт должен совпадать с портом в конфигурации сервера. Для проверки на одном ПК
можно оставить `127.0.0.1`. Все `.py` модули должны лежать рядом с `client.py`
и `control.py`; сертификат также лежит рядом с ними.

## 4. Подключиться

1. На управляемом ПК: `python client.py` → **Получить код** → **Копировать код**.
2. Передайте полный код доверенному оператору, включая `:` и секретную часть.
3. У оператора: `python control.py` → вставить код → **Подключиться**.
4. Клиент увидит окно согласия. После **Разрешить** начнётся показ экрана.
5. Оператор нажимает **Запросить управление мышью**. Клиент отдельно разрешает
   управление. Кнопки и перемещения работают в области отображаемого экрана.
6. Оператор нажимает **Включить микрофон** — клиент слышит его голос. Повторное
   нажатие закрывает устройство микрофона.
7. Завершить доступ можно кнопкой **Отключить** в любом приложении.

`Esc` в активном окне оператора отпускает мышь; `Esc` в активном окне клиента
отзывает разрешение. Эти клавиши **не глобальные**. Можно также локально переместить
мышь в угол основного экрана: следующий вызов PyAutoGUI сработает как аварийный
стоп и отзовёт управление. Основной способ остановки — кнопки в окне клиента.

Не сворачивайте клиент, если хотите иметь быстрый доступ к кнопкам остановки.
Окно клиента по умолчанию находится поверх остальных окон. На Windows управление
обычными окнами работает без администратора; защищённый экран UAC и окна процессов
с более высокими привилегиями могут не принимать ввод.

## Ограничение настоящего P2P

Signaling-сервер передаёт согласие и SDP, но не становится транспортом для экрана.
STUN помогает найти прямой UDP-маршрут; он **не гарантирует** подключение через
симметричный NAT/CGNAT или firewall, запрещающий такой трафик. При недоступном
маршруте программа завершит попытку с понятной ошибкой через 60 секунд.

Для проверки используйте одну локальную сеть, разрешите Python сетевой доступ
в firewall, либо подключите оба ПК к VPN с доступностью узлов друг другу.
Одного открытого TCP-порта signaling-сервера недостаточно для передачи медиа:
клиентам также нужен разрешённый прямой UDP-трафик на согласованные ICE-порты.

TURN здесь намеренно не настроен: TURN ретранслирует трафик, а это уже не строго
прямое peer-to-peer соединение. Для доступности «почти из любой сети», как у
коммерческих программ, потребуется добавить TURN/relay или управляемую VPN-сеть.
Возможность подключения через конкретные внешние сети в локальных тестах не проверена.

## Настройки качества и устройств

В `config.py` также находятся `VIDEO_FPS`, `VIDEO_MAX_WIDTH`, `MONITOR_INDEX`,
`AUDIO_INPUT_DEVICE`, `AUDIO_OUTPUT_DEVICE` и `STUN_URLS`.
`MONITOR_INDEX = 1` выбирает первый монитор MSS. Управление ориентировано на
основной монитор Windows; работу с дополнительными мониторами нужно проверять отдельно.
`STUN_URLS = []` отключает внешний STUN для локальной сети/VPN.

Список доступных аудиоустройств:

```text
python -m sounddevice
```

Укажите числовой ID устройства вместо `None`. Устройство должно поддерживать
48 kHz, mono, int16. Разрешите приложениям доступ к микрофону в настройках Windows.
При ошибке динамиков показ экрана продолжает работать, а клиент видит сообщение.
Эхоподавления нет — оператору и клиенту лучше пользоваться наушниками.

## Файлы и проверка

`peer.py` содержит состояние сессии и WebRTC, `media.py` — потоки экрана/звука,
`desktop.py` — мышь/DPI, `ui.py` — общие функции Tk, `protocol.py` — пакеты JSON.
Не переносите только два входных файла без общих модулей.

```text
python -m unittest discover -s tests -v
python -m pip check
```

Тесты устанавливают реальные локальные TLS- и WebRTC-соединения, проверяют отказ,
обязательное согласие, передачу видео/аудио, разрешение и отзыв мыши, отключение и
ограничение размера пакетов. Вместо рабочего стола, микрофона и мыши используются
искусственные данные: тесты не записывают звук и не двигают указатель.
Физические аудиоустройства и соединение между двумя внешними сетями нужно проверить
на ваших компьютерах.

Справка по используемым API: [aiortc](https://aiortc.readthedocs.io/en/latest/api.html),
[sounddevice](https://python-sounddevice.readthedocs.io/en/latest/api/raw-streams.html),
[MSS](https://python-mss.readthedocs.io/v10.2.0/examples.html),
[PyAutoGUI](https://pyautogui.readthedocs.io/en/latest/mouse.html).
